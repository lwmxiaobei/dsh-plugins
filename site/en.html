02 / Install guide

How to install DSH plugins

The directory provides commands pinned to a specific Git commit for reproducibility. Always review the upstream documentation and requested permissions first.

  1. 01

    Find a plugin

    Search by name, capability, package, or owner. Use language and license filters to narrow the directory.

  2. 02

    Review its details

    Open the detail page to inspect the repository, version, license, last update, and pinned commit hash.

  3. 03

    Copy and run

    Copy the install command and run it in the environment hosting DeepSeek Harness. Follow upstream instructions for configuration.

03 / Directory policy

How the catalog is maintained

DSH Plugins discovers candidate repositories through the GitHub dsh-plugin topic, then checks their plugin manifest, package metadata, and install requirements. Public data is refreshed regularly and every detail page states when its snapshot was updated.

Inclusion is not a security audit or official endorsement. We preserve direct links to upstream source, never fabricate ratings, and do not present an unknown license as permission to reuse. Corrections are welcome through GitHub.

04 / FAQ

Frequently asked questions

Answers about plugin discovery, install commands, and catalog data.

What is a DeepSeek Harness plugin?

It is an extension installed into DeepSeek Harness to add tools, user interfaces, model integrations, memory, browser automation, or other capabilities. Each plugin is maintained by its upstream repository.

Why does the install command include a commit hash?

A pinned commit prevents a moving upstream branch from returning different code for the same command. It makes the catalog snapshot and installed source easier to verify and reproduce.

Are listed plugins security audited?

No. The directory validates public metadata and basic plugin structure, not the complete code, security, or privacy behavior. Review source, permissions, and license before installing.

How do I submit or update a plugin?

Add the dsh-plugin topic to a public GitHub repository and keep its plugin manifest complete. The next catalog sync can discover and validate it, or you can open an issue in the directory repository.
